> **讀者正在問：** 控台一直自動儲存，是否代表不用另外備份？一場校內演出究竟要保留多少個檔案？  
> **文章承諾：** 看完你能建立一套不依賴單一控台、能回到上一個穩定版本的 Show File 備份制度。

Save 和 Backup 不是同一件事。Save 把最新修改寫入工作檔；Backup 則把可用版本放到另一個檔案、另一個儲存裝置，最好還有一份不與控台放在同一位置。

## 應多久儲存一次？

沒有一個適合所有演出的分鐘數，但可以訂下不需要思考的觸發點：

- 完成一段重要 Cue、Effect、Patch 或 Palette 後立即儲存。
- 大量修改、合併 Cue、更新控台軟件或嘗試不熟悉功能之前先備份。
- 編程期間至少每小時建立一次可回復版本；工作密集時要更頻密。
- 每次離開控台前，即使只是上台調燈，也先 Save 並輸出外置副本。
- 每日排練結束後保存 Daily Archive，不再覆寫。

自動儲存只能減少當機造成的損失。若最新狀態本身已被錯誤修改或檔案損壞，自動儲存亦可能忠實地保留錯誤。

## 至少保留三層可用副本

一場香港中學禮堂演出的最低實用基準是：

1. **Working File：** 控台上正在使用的工作檔。
2. **Stable File：** 最近一次完整測試、確認可演出的穩定版本，不與工作檔互相覆寫。
3. **External Copy：** USB、備用控台或另一部電腦上的最新副本。

此外保留每日版本和重大里程碑，例如首次走完 Act 1、Dress Rehearsal 完成、正式演出前。副本數量不是愈多愈安全；沒有清楚名稱的一堆 `final_final2`，在事故時反而找不到真正版本。

## 版本命名要讓別人也看得懂

可使用以下格式：

`SchoolMusical_2026-08-02_v07_after-dress-rehearsal`

名稱最少包含節目、日期、遞增版本和狀態。若是測試分支，加上 `TEST`；若已完整驗證，加上 `STABLE`。不要只依靠檔案修改時間，也不要一直覆寫同一個主檔。

## 外置備份仍要實際測試

USB 有檔案不代表另一部控台讀得到。正式演出前應：

- 把 Stable File 載入備用控台或 Offline Editor。
- 確認控台軟件版本、Fixture Library 和授權相容。
- 抽查 Patch、Group、Palette、關鍵 Cue、Timecode 和外部觸發。
- 把最新檔案交給指定負責人，記錄存放位置。

## 檔案遺失後怎樣應變？

1. 停止繼續儲存，避免覆蓋仍可救回的版本。
2. 記錄當機時間和最後完成的修改。
3. 載入最近的 Stable File，不要憑名稱猜測最新版。
4. 由排練筆記重建遺失部分，先處理安全、Patch、Blackout 和主要 Cue。
5. 從演出前一段開始完整測試，再決定是否恢復演出。
6. 事故後保留故障檔和記錄，改善下一次備份流程。

真正的主檔不是檔名寫着 `MASTER` 的那一份，而是**已測試、可讀取、能在需要時迅速恢復**的那一份。
